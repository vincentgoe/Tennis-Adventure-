# AGENTS.md

Guidance for AI coding agents (and humans) working on **Plot Twist**, a short
point-and-click tennis mystery built for the course "Introduction to
Programming" (Nova SBE).

The requirements are in `docs/product-brief.md` (the BRD). The story design and
all approved texts are in `docs/story.md`. Each feature has a task spec in
`specs/`. `docs/acceptance.md` maps every BRD requirement to its tests and to
where it shows in the game. Read these before changing behaviour.

## Commands

All commands go through `uv`. Do not use `pip` or a manually activated venv.

| Task                    | Command                              |
| ----------------------- | ------------------------------------ |
| Install / sync          | `uv sync`                            |
| Run the app             | `uv run streamlit run app.py`        |
| Run all tests           | `uv run pytest`                      |
| Redraw the images       | `uv run python tools/draw_assets.py` |
| Add a dependency        | `uv add <package>`                   |
| Add a dev tool          | `uv add --dev <package>`             |

Notes:

- The parent folder name ends with a space (`Introduction to Programming `).
  Always quote paths in shell commands.
- The app caches `story.json` and the images. After changing them, **restart
  the app** (stop it, start it again) to see the change.
- To start over without the "New game" button, delete `plot_twist.db`.

## Project structure

```
app.py                  Streamlit screens only: render state, collect clicks, save
logic.py                Game rules: pure functions, no Streamlit, no SQLite
db.py                   Persistence: save / load the game progress in SQLite
story.json              Story content: scenes, actions, conditions, items, matches, endings
components/scene_view/  Scene view (HTML + plain JS): hotspots, walking, speech bubbles,
                        text boxes, close-ups; shows the ending pages too
components/match/       Tennis minigame (HTML + plain JS, canvas)
assets/                 SVG images, all generated by tools/draw_assets.py
tools/draw_assets.py    Draws every image in assets/ (block style, SVG animations)
tests/                  pytest tests
docs/                   BRD, story design, acceptance overview
specs/                  Task specs, one per feature (Why / What / Out of scope / Done when)
AGENTS.md               This file
```

Dependencies point in one direction only: `app.py` → `logic.py` and `db.py`;
`db.py` imports only the `GameState` dataclass from `logic.py`. `logic.py` must
not import Streamlit or `db.py`, so it can be tested without a UI or database.

The two components know **no rules**. Python decides which hotspots exist,
whether an action is allowed, what a match result means and which text is
shown. The components only draw, animate and report what was clicked or how a
match ended. Both talk to Streamlit with its plain `postMessage` protocol, so
there is no build step and no extra package. The pixel font Press Start 2P is
stored next to each component with its licence (`PressStart2P-OFL.txt`).

## Story as data

Story content is **data** in `story.json`, kept separate from the code.
`logic.py` reads it and never hard-codes scene names, items or texts. SQLite
stores **only the player's progress**: scene, items, flags, choices, match
results and the ending. The story content is never written to the database.

Main keys (see the specs for details):

- **Conditions** (`requires`, `when`, `hide_when`): `items`, `not_items`,
  `flags`, `not_flags`, `choice_made`, `no_choice`, `match_due`. Entries in
  `texts`, `blocked_text`, `images`, `outcomes` and the `player` list are
  checked in order; the first matching one wins.
- **Scenes:** `name`, `player` (position and scale), `sky` (horizon, for the
  sun), `dialog_position`, `texts` (`text` + `image`), `actions`.
- **Actions:** `id`, `label`, `requires`, `hide_when`, `blocked_text`,
  `effects` (`move_to`, `add_item`, `set_flags`, `set_choice`, `show_text`,
  `play_match`), `speaker` / `speaker_at`, `closeup`, `preview`, `icon`,
  `hotspot` (`x`, `y`, `w`, `h`, `name`, `label_at`, `marker`, `direction`,
  `walk_to`, `drop`). An action with a `blocked_text` is shown and explained
  when blocked; without one, it is hidden.
- **Matches:** `rounds` with `requires` and `outcomes` (fixed `result`, `text`,
  `effects`, and `game` settings for the minigame). The story's result always
  wins (`logic.apply_match_result`).
- **Endings:** `when_final`, `title`, `pages` (`name`, `text`, `image`,
  `images`, `captions`, `captions_until`).
- **Other:** `player` (sprite per state), `items`, `ui_texts`.

A new game resets progress and keeps the story content (BRD PT R4). The local
database file is not committed (`*.db` and `*.sqlite` are in `.gitignore`), and
neither are secrets (`.env`).

## Testing rules

- Tests are written **first**, then the feature is implemented.
- Tests must **not** be weakened, skipped, marked xfail, or deleted to make the
  code pass.
- A test that turns out to be wrong is corrected only explicitly, with a
  reference to the BRD rule or spec it contradicts, and that change is stated
  in the commit message (example: `bigger-world`, three story tests).
- Rule tests target `logic.py` directly, mostly with the small test story in
  `tests/conftest.py`. Tests in `tests/test_story.py` and `tests/test_world.py`
  check the real `story.json` (images exist, both endings are reachable, …).
- Persistence tests use a temporary database file (`tmp_path`), never the real
  game database.
- The JavaScript in `components/` is not covered by pytest. It is checked by
  playing the game in the browser (part of every feature's manual check).

## Branch and feature workflow

1. `main` holds the finished, merged features. Features are never developed on
   `main`.
2. Create a feature branch.
3. Write or update the spec in `specs/<branch-name>.md`.
4. Write the tests.
5. Implement until `uv run pytest` is fully green.
6. Verify by hand: run `uv run streamlit run app.py`, play the feature,
   **stop the app, start it again**, and check that progress was restored.
7. Commit, push, open a pull request, review, merge into `main`.

A feature is not done until steps 5 and 6 have both passed.

## Working agreement for agents

- At the start, the author wanted to write game logic and tests themselves;
  from the first feature on, they asked the agent to implement features. The
  author still decides on story, texts and design: **new story texts need the
  author's approval** before they go into `story.json`.
- Work in small steps; show the result and ask before larger changes.
- If the BRD or a spec is ambiguous, ask instead of filling the gap.
- Code, file contents and commit messages are in English. Explanations to the
  author are in German.
